# 同一角色换场景，提示词怎么写？拆开身份要求与镜头变量

![同一角色换场景，提示词怎么写？拆开身份要求与镜头变量](cover.png)

让同一个角色出现在不同场景，提示词里不必每次重新描述一遍长相。参考图已经表达清楚的特征，可以作为身份依据；文字重点说明这次要改什么，以及哪些要求仍需保留。

可以把身份要求和镜头要求分开写，后续修改时更容易对照。

## 固定部分：这个角色是谁。

指定使用哪张参考图，列出项目必须保持的特征，例如人物身份、发型、某件配饰。并不是所有细节都必须固定：换装项目可以改衣服，连续剧情则可能需要同一套服装。先按自己的任务确定。

## 变化部分：这次镜头发生什么。

把场景、动作、景别和光线写在另一段。以后换镜头时，就能看到自己改了哪些条件。

下面用一个虚构成年角色说明结构。这是新编的提示词示例，没有对应的出图实测，使用时需要附上自己的参考图，并确认工具支持参考图编辑。

```text
使用已附参考图中的同一位成年角色作为身份依据。
保留角色的面部身份、短发、深色外套和圆形耳饰。

本次只把场景换成街边咖啡店，角色坐在窗边看向窗外。
使用腰部以上的中景和柔和日光。
保持人物可辨认，不重新设计其外貌。
```

下一张换到车站时，可以先只改场景和动作，保留身份部分。如果连外貌描述也一起改了，就很难判断差异来自哪项调整。

出图后，仍需拿结果和基准图核对。出现偏差时，记录具体问题：“侧脸轮廓变了”“耳饰不见了”，比写“感觉不对”更方便继续修改。已经偏离身份的结果，也不宜未经审核就作为下一轮的新基准。

准备批量做分镜，可以先试简单背景，再试角度或动作变化，最后看更远的景别。一次逐步增加一种变化，观察哪一步开始出现问题。保留模型版本、参考图、提示词和参数，后续才能对照。

这套写法帮助你把要求说清楚，并不保证每次都得到同一张脸。人物保持、画质和构图也需要分别检查。

## 批量分镜时，先把变量列出来

| 项目 | 示例要求 | 是否在本轮修改 |
| --- | --- | --- |
| 身份依据 | 已附参考图中的成年角色 | 保持 |
| 项目要求 | 短发、圆形耳饰 | 按项目保持 |
| 场景 | 街边咖啡店 | 可以修改 |
| 动作 | 坐在窗边看向窗外 | 可以修改 |
| 景别与光线 | 中景、柔和日光 | 分轮修改更便于对照 |

这里的“保持”是向模型提出的要求，不是模型能力承诺。表格也不能代替图片上传：请求只带文本时，文字中的“已附参考图”不会自动把文件送到服务端。

生成结果审核时，先看身份是否符合基准，再看这个镜头需要的服装、动作和构图。把具体偏差写回本次记录；没有通过审核的结果，不直接替换原来的基准图。换装项目可以调整服装保持项，不必为了照抄模板锁住所有细节。
